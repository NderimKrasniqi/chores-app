# Interaction Principles

**Status:** Draft

## Responsibilities before extras

Normal responsibilities should feel primary.

Extra earning opportunities should feel available and motivating without
overshadowing expected responsibilities.

## Submission is not earning

A submitted chore is waiting for Parent review.

Never visually communicate the value as earned until approval.

## Claims are commitments

Claimable chores should not feel like casual shopping-cart additions.

The UI should clearly communicate:

- deadline
- monetary value
- locking
- unclaim rights
- penalty consequence

## Server-confirmed actions

Claim, unclaim, submit, approve, reject, and payout settlement require
authoritative server confirmation.

The UI should support:

- checking
- pending
- confirmed
- failed
- retry
- unavailable offline

Do not present optimistic finality before the server confirms the action.

## Calm urgency

Urgent information must be easy to notice without turning the app into
an alarm-heavy experience.

Use hierarchy, concise text, iconography, and restrained semantic color.

## Privacy

A Child may see household activity and individual chore values.

Do not expose another Child's running balance or detailed financial history.
